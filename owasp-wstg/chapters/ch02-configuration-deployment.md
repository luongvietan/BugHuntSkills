# 4.2 Configuration & Deployment Management (WSTG-CONF)

Source: WSTG v4.2 §4.2. Tests the platform around the app: server config, leftover artifacts, admin surfaces, HTTP-layer policy, and cloud/DNS hygiene. Most findings here come from "deployed and forgotten" — defaults, samples, backups, stale DNS.

## Test list

- **WSTG-CONF-01 — Network infrastructure configuration.** Objective: review each infra element (web server, DB, auth, proxies) for known vulns and weak config. Procedure: after INFO-10 architecture mapping, check each element's version against advisories; review admin tools used to maintain them; validate required-ports list. Interpretation: scanner version-matching produces both false positives (backported patches) and negatives (obscured banners) — internal version info beats banner guessing.
- **WSTG-CONF-02 — Application platform configuration.** Objective: verify defaults/samples removed, no debug code, logging in place. Procedure: probe for known sample files (CGI scanners carry lists of stock IIS/Apache/Oracle samples); review comments in served content; check custom error handling for 40x/50x; verify server modules minimized and service runs with least privilege (gray-box: config review, CIS-CAT/benchmarks). Interpretation: sample apps have real CVEs (CodeBrws.asp traversal, sendmail.jsp); leftover debug = free info.
- **WSTG-CONF-03 — File extensions handling for sensitive info.** Objective: learn tech via extensions and find extension-handler weaknesses. Procedure: request resources with varied extensions per directory (`.bak`, `.old`, `.inc`, `.asa`, `.config`, `~`); note which execute vs return as text vs download; check upload-extension validation for bypasses. Interpretation: `.inc`/`.bak` served as plain text leaks source code including connection strings; inconsistent handling between load-balanced nodes is itself a finding.
- **WSTG-CONF-04 — Old backup and unreferenced files.** Objective: find forgotten files with sensitive content. Procedure: enumerate via inference — clone known filenames with backup suffixes (`.bak`, `.old`, `.orig`, `.save`, `.swp`, `~`, `.copy`, `_1`, `.txt`, case variants), crawl archives (`.zip`, `.tar.gz`), try editor temp files and `web.config` backups; check CVS/SVN/`.git` leftovers and unreferenced pages via spider + Wayback. Interpretation: source code in backups gives white-box access to an app you only had black-box on; `.git` often reconstructs the whole repo.
- **WSTG-CONF-05 — Enumerate infrastructure & application admin interfaces.** Objective: find hidden privileged interfaces. Procedure: dir/file brute force (`/admin`, `/administrator`, `/manager/html`, phpMyAdmin, WebSphere `/admin*` paths); read source for admin links/comments; check docs for default paths; probe alternate ports (Tomcat on 8080); tamper params/cookies (`admin=no`, `useradmin=0`); try default creds once found. Interpretation: an exposed admin panel + default password is full compromise; even a login page expands attack surface.
- **WSTG-CONF-06 — Test HTTP methods.** Objective: enumerate supported verbs and abuse them. Procedure: `OPTIONS` + nmap `http-methods` script; try `PUT /test.html` then GET it back (2xx = arbitrary write — clean up after PoC); replay auth-gated requests with `HEAD`/`POST`/junk verbs (`BILBAO`, `CATS`) for access-control bypass; test `TRACE`/`CONNECT` for XST; check `X-HTTP-Method-Override`/`X-Method-Override` headers. (WSTG-INPV-03 verb tampering merged here.) Interpretation: verb-based access control that only inspects GET/POST is bypassable with any other verb.
- **WSTG-CONF-07 — Test HTTP Strict Transport Security.** Objective: confirm HSTS present and correctly scoped. Procedure: `curl -s -D- https://target | grep -i strict`; check `max-age` ≥ ~6 months, `includeSubDomains`, `preload`; verify base domain, not just www. Interpretation: missing HSTS on a domain sharing cookies with subdomains enables MITM downgrade and cookie theft (SESS-09).
- **WSTG-CONF-08 — Test RIA cross-domain policy.** Objective: review `crossdomain.xml`/`clientaccesspolicy.xml` (Flash/Silverlight/Java). Procedure: fetch both from root and each discovered folder; flag `domain="*"`, wildcard header grants, `permitted-cross-domain-policies="all"`, `secure="false"`. Interpretation: wildcard policy = cross-domain read of authenticated content and CSRF-token bypass via the RIA plugin; legacy tech but still found on old estates.
- **WSTG-CONF-09 — Test file permissions.** Objective: find critical resources readable/writable by wrong actors (mostly gray-box/hosted testing). Procedure: `namei -l`/`ls -l` on web roots, configs, keys, logs, executables, DB files, temp/upload dirs; on Windows use AccessEnum/AccessChk. Interpretation: world-readable config with keys or world-writable upload dir turns a foothold into compromise (CWE-732).
- **WSTG-CONF-10 — Subdomain takeover.** Objective: find DNS records pointing at unclaimed/dead resources. Procedure: enumerate subdomains (dnsrecon, Amass, Sublist3r, theHarvester); `dig` each for `NXDOMAIN`/`SERVFAIL`/`REFUSED`; for CNAMEs check whether the target service (GitHub Pages, S3, Heroku, Azure…) allows claiming; for A records whois→provider then probe HTTP for provider 404 pages; check NS records pointing at expired domains (highest impact — full zone control). Interpretation: claimable dangling record = serve content, steal scoped cookies, phish under the real domain.
- **WSTG-CONF-11 — Test cloud storage.** Objective: assess object-store access control (S3 et al). Procedure: spot bucket URLs in traffic (`bucket.s3.region.amazonaws.com/key` or path-style); try unauthenticated read `curl -X GET https://<bucket>/<object>` and a harmless write `curl -X PUT -d 'test' https://<bucket>/test.txt` (delete after); with aws-cli: `aws s3 ls`, `aws s3 cp`, `aws s3 rm`. Interpretation: public-read leaks data; public-write enables content poisoning/malware hosting — always clean up test objects.

## Common findings

`.git/HEAD` fetchable; `file.php.bak` returning source; PUT-enabled directories; `/manager/html` with `tomcat:tomcat`; permissive `crossdomain.xml`; dangling CNAME → claimable Heroku/GitHub/S3; world-readable S3 buckets; HSTS missing on parent domain.

## Escalation notes

Backup source → hardcoded keys → ATHN-02-style logins. Admin interface + default creds → full control, then pivot to CONF-09. Subdomain takeover → cookie scope abuse (SESS-02 Domain) and trusted-content phishing. Cloud write → stored XSS host (INPV-02) or supply-chain via asset injection. Report the PoC and remove anything you uploaded.
